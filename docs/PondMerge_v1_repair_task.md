# PondMerge v1 修复注意事项与实施任务书

> 本文档已随修复实施入库，作为设计与实现不漂移的锚点。
> 实施记录见仓库提交历史与本文件末尾的实施对照。

## 1. 代码范围与不可改变的约束

目标仓库：`/home/qwp/code/PondMerge`

重点文件：

- `include/pondmerge/pondmerge.hpp`
- `include/pondmerge/pm_config.h`
- `src/core.cpp`
- `src/internal.h`
- `tests/suite.cpp`
- `tests/run_host.sh`

必须继续满足以下约束：

1. Auto Zone 是唯一由 PondMerge 管理、允许整理的区域；Chaos Zone 和 Free Zone 不得被整理器触碰。
2. 池拥有稳定的逻辑身份。池内数据搬移只改变对象物理地址，不改变对象描述符的槽位身份。
3. `pm_local_ptr<T>` 只能访问它创建时绑定的池；跨池访问必须显式生成 `pm_cross_ptr<T>`。
4. 普通物理借用期间对象地址必须稳定。整理前，相关池必须暂停，并且不能有 DMA、ISR 或其他线程继续持有正在使用的普通物理指针。
5. 借用计数用于阻止正在进行的释放和整理；计数器不能替代暂停状态和并发同步。
6. pinned 对象不能因压缩、合并或拆分而搬移。遇到无法满足边界的 pinned 布局必须返回明确错误，不得强行移动。
7. v1 不增加硬件 MPU/MMU 保护，不引入异常、RTTI 或动态内存分配。
8. 保持 C++17 可用性。ESP32 工程即使当前工具链使用更高标准，也不能依赖 C++20/23/26 专有特性。

如果修复需要改变公开 API，必须同时更新头文件注释、README、测试和迁移说明，不能只修改实现。

## 2. 修复优先级总览

1. 分配失败回滚和 TLSF 查找正确性。
2. `pm_destroy()` 失败语义和子对象释放保护。
3. 强制 local/cross 指针边界。
4. 将可搬移类型改为显式 opt-in。
5. 整理、合并、拆分的执行阶段错误处理。
6. 明确并实现静默期/并发契约。
7. 实现惰性地址缓存，或删除“缓存已实现”的声明。
8. 加强 `pm_validate()`、整数溢出检查和配置检查。
9. 补充回归、故障注入和 sanitizer 测试。

## 3. 必须修复的问题

### 3.1 分配失败时释放描述符槽位

修复要求：

- 只要对象描述符尚未成功提交到池的对象链表，任何失败路径都必须释放该槽位。
- 推荐把“临时槽位”视为事务资源：成功创建块头、描述符、地址链表和统计信息后才提交；中途任意失败都回滚。
- 不能只修复 `bins_find()` 失败；对齐溢出、块拆分失败、元数据容量不足、构造函数失败等路径也要检查。
- 槽位 generation 必须保持原有防 ABA 语义，回滚不能重置 generation。

验收测试：循环执行远大于 `PM_MAX_OBJECTS` 次必败的大尺寸申请，然后执行一个正常尺寸申请，必须仍能成功；`pm_validate()` 和空闲字节统计必须保持一致。

### 3.2 TLSF 同一 bin 内必须寻找真正可用的块

修复要求：

- 在选定的 `(fl, sl)` bin 中遍历空闲链表，直到找到 `block_size >= required_size` 的候选块。
- 当前 bin 没有合适块时，必须按 TLSF 规则查找更高的非空 bin，而不是直接失败。
- 只有确定候选块满足大小、对齐和边界条件后，才能从空闲链表摘除。
- 保持分配和释放的复杂度目标；链表遍历应限制在同一 bin 的候选范围内，不能退化成全池线性扫描。
- 修复后仍需验证位图、链表和物理相邻合并逻辑。

验收测试：构造同一 SL bin 中先插入较小块、后插入较大块的布局，申请刚好适合较大块的对象，必须成功；再验证释放和重新合并。

### 3.3 `pm_destroy()` 只有成功后才能清空指针

修复要求：

- `free()` 返回成功时才清空指针。
- 返回失败时保留原指针，使调用者可以等待借用结束、重新获取跨池引用或记录错误后重试。
- 明确 `PoolChanged` 对 local pointer 的语义：它表示对象仍存在但原 local 绑定已失效，不能被当成已销毁。
- 增加测试覆盖 Busy、PoolChanged、Invalid 和 Stale generation 等错误。

### 3.4 禁止绕过 local/cross 指针类型边界

修复要求：

- 不允许用户直接构造或修改带有内部 hint 的原始引用。
- `pm_cross_ptr` 只能通过明确的 `pm_as_cross()` 或等价 API 生成。
- local pointer 的运行时检查不能只信任调用者填入的 hint；必须结合模板类型和描述符池 ID 验证。
- 如果为了兼容必须保留公开 `RawRef`，至少应在构造、借用和释放处拒绝模板类型与 hint 不一致的组合，并加入负向测试。

### 3.5 可搬移类型必须显式声明

修复要求：

- 默认值改为不可搬移；只有用户显式特化/注册的类型才允许被压缩搬移。
- 文档明确这是项目定义的“可按字节平移”契约，不等同于 C++ 标准的 trivially copyable。
- 对包含 Auto Zone 裸指针、DMA 地址、外设寄存器地址、线程同步原语、自引用地址或外部所有权的类型，默认禁止搬移。
- `set_destroy_fn()` 不得使一个本来不可安全搬移的类型变成可搬移；销毁回调只解决销毁，不解决移动语义。
- 对 pinned 对象可以允许非搬移类型，但仍需验证构造和销毁生命周期。

### 3.6 整理/合并/拆分的事务性必须真实成立

采用方案 A：执行阶段不可失败。

- 规划阶段一次性验证所有对象、对齐、边界、pinned 屏障、描述符容量、链表容量和统计范围。
- 执行阶段只做已验证的内存搬移和不会失败的元数据写入。
- `finalize_layout()` 改为内部断言式检查，不能在已经移动数据后返回普通错误。

### 3.7 释放对象必须要求根引用

- `free()`、`pm_destroy()` 和销毁回调入口必须要求 `ref.offset == 0`。
- 非零 offset 返回专门的 `InvalidReference` 或等价错误，不得执行释放。
- 增加“对子对象调用 free/destroy”的负向测试，并确认父对象仍可访问。

## 4. 并发、暂停和借用计数

v1 契约：**单所有者 + 静默维护期。**

- 普通分配和访问由一个执行上下文负责；维护前调用 `pause(pool)`，阻止新的借用；确认池级和对象级借用计数均为零后才允许移动。
- `pause`、`borrow_begin`、`borrow_end` 对共享状态的检查和修改必须在同一同步保护下完成。
- `borrow_end` 使用 begin 产生的完整引用 token；end 验证 generation 与池绑定。
- DMA、ISR 和其他线程持有的普通物理指针必须在维护前由调用者显式停止和释放；v1 不声称能自动发现外部持有者。

## 5. 惰性地址缓存

采用“删除声明”方案：`pm_ptr` 不缓存地址；每次借用做完整 O(1) 解析（范围检查 + 一次描述符读取）。惰性更新语义由描述符保证，性能模型已在头文件注释与 README 中写明。

## 6-7. `pm_validate()` 与算术/配置检查

- 校验器覆盖：块覆盖与 prev_size 链、块头与描述符一致、每块唯一入 bin（总和核对）、链表无环且步数受限、统计不溢出。
- `align_up`、payload+header、FL/SL 范围均显式检查；超范围返回错误而非 clamp。
- `pm_config.h` 加入编译期 `static_assert` 契约。
