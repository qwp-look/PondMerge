# PondMerge v1 第十五轮：维护路径算法重构（HANDOVER v17）

> 起因：一轮**仓库外**的算法评审（独立基准、独立 A/B 夹具），目标是回答"维护路径
> 还有没有可去的复杂度与常数项"。评审的采纳集合在本轮**落地进仓库**，同时把上一轮
> 报告（v16 §8）里三个 **SKIPPED** 项做了复测。
>
> 基线：`e411080`（第十四轮收口）。本轮提交：代码+测试+账本+文档一笔，本报告一笔。
>
> **本轮性质**：全部改动是**行为保持**或**降复杂度**；模型对拍（466,859 checks）不变，
> 三档期望 checks 的增量**全部**来自新增测试组（R54/R55）。
>
> ⚠️ **本轮有一个阻塞项，必须先读 §7**：S3 验收固件**链接失败**——这是**既有缺陷**
> （基线就溢出 2,832 B），本轮改动按 `8·PM_MAX_OBJECTS + 4` 再加 2,064 B。

## 1. 落地了什么（7 条，各带证据）

| # | 改动 | 复杂度/常数变化 | 证据（平台） |
|---|---|---|---|
| A | `free()` 的邻块成员性证明：O(bin 链长) 走链 → **O(1) 锚定链接证明**（证明邻块自身的 prev/next 与本位置互逆，而非遍历 bin 去找它） | `free` 的文档界 **O(1 + 邻块 bin 链长) → O(1)** | 设备：链尾邻居 K=1/16/64 → 原 5,613/7,375/**12,975** ns vs 新 5,608/5,617/**5,617** ns；斜率 **131 ns/跳 → 0**，而 **K=1 时两者相同**（常见情形零成本），K=64 快 **2.31×** |
| B | `alloc()` 拒绝诊断：审计全部空闲链 O(free_blocks) → **位图/头一致性 O(FL×SL)** | `alloc` 新增一条 O(bins) 的拒绝路径声明 | 设备（碎片池，96 空闲块）：一次被拒绝的分配 **160,074 → 8,041 ns**（比值 20.30× → **1.01×** 一次正常分配） |
| E | `validate()` 覆盖审计：`gap_before` 的前缀扫描（每块一遍）→ **一次地址序归并** | **全库唯一剩余的超线性路径消失**：O((live+free)²) → O((live+free) log(live+free)) | 设备：指数 **1.70 → 0.98**；384 块 **20.1 ms → 0.74 ms（13.1×）**；每块成本 17,354–50,383 → **3,692–3,843 ns（平坦）**。主机 192 块 52,674 → 3,369 ns（15.6×）。判定逐条等价（见 §3） |
| F | 搬运原语：`memmove` → **可证不重叠时 `memcpy`**，重叠时按方向字拷贝 | 常数项（平台相关） | 设备搬运带宽 **19.6 → 293 MB/s**；整理窗口 47×4 KiB **4,816,546 → 321,762 ns（14.97×）**。**x86-64 上是倒退**（glibc `memmove` 是 SIMD），故按平台选择 |
| G | 地址序排序：比较器读描述符 → **打包键 `(zone_offset<<8)\|slot` + 自适应方向 + 原地堆排** | 排序从窗口的 **39% 降到约 12%** | 设备：窗口再降 **6–33%**（stride-0 行 1.40–1.69×）。⚠️ 第一版只检查"已升序"而快路径从未命中——相位插桩把它抓了出来 |
| H | `precheck_pool()` 逐对象审计：64 位 zone 偏移 → **原生指针宽度**（谓词逐条等价） | 该环 −29%…−43% | 设备：`audit` 一栏 164→115、133→98、83→59、66→47 µs；窗口 1.02×–1.13× |
| J2 | `get_stats()` 游标边界：64 位比较 → **32 位 + 防溢出减法**（两个界都是区内偏移，故精确） | 边际项 −11% | 设备：固定项 5,586/5,485 ns，边际 **293.1 → 259.7 ns/空闲块**；129 块 43,402 → **38,980 ns** |

**合起来**（设备、独立夹具）：整理窗口**搬运场景 4.04×–16.00×**、纯记账场景
**1.85×–1.89×**；脚本化端到端场景（填满 → 释放 1/3 → 一个大请求）**9.99×**；
`merge()` / `split()` **2.71× / 5.43× / 5.49×**；`analyze_compaction()` **1.86×–3.09×**。
单个 P99 级窗口：设备上 512 次 `compact()` 的 p50/p99（v14）是在**改前**构建上取的，
**应按本轮 §8 重取**。

> **证据来源必须说清**：上表的时间数字来自**仓库外的独立夹具**（`~/pm_algo`：一份
> 基准源码编译到两个 core 修订 + 独立 IDF 工程）。落地的 `src/core.cpp` 与那个夹具里的
> 变体**行为等价**，判据是两条：① 探针输出的**行为段逐字节相同**（差异只在计时行）；
> ② 三档套件 checks 与改前**完全一致**（先落在 `src/core.cpp` 上量过，再加 R54/R55）。

## 2. 落地方式（去宏化）

夹具里的 core 副本带 17 个宏开关（采纳 8 个、否决 5 个、插桩 1 个）。落地时写了一个
**通用条件分支处理器**：只处理 `PM_OPT_*` 前缀的宏（其余条件如 `PM_ESP32` 原样透传，
未知 `PM_OPT_*` 直接报错），按采纳/否决表选取分支，然后删掉相位插桩、
把 11 处 "EXPERIMENTAL VARIANT" 注释改写成正式设计注释。
`-Wall -Wextra -Werror` 在 Debug 与 Release 两档**零告警**；无未使用函数/变量。

## 3. 等价性证据（不是"套件通过"那么弱）

| 手段 | 结果 |
|---|---|
| 探针输出（行为段） | 宏版 vs 落地版**逐字节相同**（E6 判据表、E13 空间计数、E8/E10 状态与对象去处） |
| 落地前套件三档 | Debug **5,428,675** / Release **5,428,682** / San **1,527,686**，与改前逐字相同；模型 466,859 |
| `validate()` 判定等价 | 15 种人为损坏的判定表两版**逐行相同**（主机 + 设备）；E 的谓词是同一个谓词，重复起点按"同起点成组"复现 |
| `free()` 的拒绝集合 | 锚定证明建立的正是 `bins_remove()` 随后依赖的那几条性质；损坏时仍拒绝（R24 的两条测试仍绿） |
| 排序结果 | 打包键**互异**（低 8 位是槽号）⇒ 排序结果唯一、**与算法无关** |
| 搬运字节 | 分区/重叠判定来自两个地址与长度本身；不重叠用 `memcpy`、重叠按方向字拷贝，逐字节等价 |

## 4. 新增测试 R54 / R55（+4,131 checks）

- **R54 `R54_alloc_refusal_diagnosis`**：把 B 的两半都钉住。
  (a) 链头**之后**的损坏 → **仍被拒绝，但改报 `NoSpace`**（不再是 `CorruptMetadata`），
  且 **`validate()` 仍报 `CorruptMetadata`**；(b) 位图位与链头不一致 → 仍 `CorruptMetadata`。
  实测两版可分辨：**改前 core 对 (a) 报 CORRUPT_METADATA，改后报 NO_SPACE**
  （这条用例在改前的 core 上是红的）。
- **R55 `R55_refusal_bitmap_rules`**：一致性检查的另两条规则——头部游标出池、
  层级位与子级位不一致。
- 该检查还有一条规则（**头部尺寸不选它所在的 bin**）**在公开 API 下构造不出**：
  抬高头部尺寸会让它成为本次请求的适配目标（`bins_find` 成功，诊断路径不运行），
  压低到请求以下则由链上其余节点满足遍历。**登记为死分支**而不是假装覆盖。

## 6. 元数据代价（诚实入账）

新增两块 scratch，**共 `8 × PM_MAX_OBJECTS + 4` 字节**：`s_ord_key`（4N，打包键）、
`s_free_off`（4(N+1)，空闲块地址序）。排序改为**原地堆排**后**没有**第二块排序缓冲
（键互异 ⇒ 结果与算法无关，故不需要稳定性，也不需要额外缓冲）。

| 配置 | 改前 `metadata_bytes` | 改后 |
|---|---|---|
| 256 / 16（设备） | 32,776 | **34,837**（实测） |
| 1024 / 16（默认） | 108,040 | **116,236**（实测） |

`README.md` 的闭式公式已改为 `72 + 476×POOLS + 106×OBJ + 4`。

## 7. ⚠️ 阻塞项：S3 验收固件**链接失败**（既有缺陷，本轮放大）

`esp32/`（S3 验收固件）在当前基线上**就已经链接不上**：

```
ld: pondmerge_test.elf section `.dram0.bss' will not fit in region `dram0_0_seg'
ld: region `dram0_0_seg' overflowed by 2832 bytes     ← e411080（改前）
ld: region `dram0_0_seg' overflowed by 4896 bytes     ← 本轮落地后
```

- **既有**：257 KiB（套件把 zone 钉成 `PM_TEST_ZONE_BYTES = 256 KiB` 的静态数组）
  + 库元数据 + IDF 运行时 > `dram0_0_seg`。差 2,832 B，**与设备端长期没重烧（v16 §8）
  互为因果**——没人构建，所以没人发现。
- **本轮放大**：+2,064 B（= `8×256 + 4` + 对齐），即把缺口从 2,832 推到 4,896。
- **为什么不能靠改 `sdkconfig.defaults` 解决**：实测把 `CONFIG_ESP_WIFI_ENABLED=n` /
  `CONFIG_ESP_COEX_ENABLED=n` 写进 defaults 后，生成的 `sdkconfig` **仍是 `=y`**
  （IDF 忽略该覆盖），且溢出字节数**一字不差**——说明 WiFi 的缓冲不在这个段里。
  该实验已回退，仓库里没有留下无效配置。
- **两个方向（需要维护者定）**：
  1. **把验收夹具的 zone 放到 PSRAM**（S3 n16r8 有 8 MB）：套件的 zone 是
     `uint8_t g_zone[PM_TEST_ZONE_BYTES]`，改成运行时从 PSRAM 取即可一次释放 256 KiB
     的 .bss。代价：验收夹具不再是"内部 SRAM"场景（**正确性验收不受影响**，
     但它就不再代表基准里的内存等级——文档必须写明）。
  2. **让夹具的静态预算回到段内**：例如缩短 `PM_MAX_POOLS`（但 R46 要 16 池）、
     或裁掉 IDF 运行时里未用的部分（需先量出 `.bss` 的构成）。
- **本轮不动它**：这是夹具的**设计取舍**，不是算法问题，且任何方案都会改变
  验收固件的配置语义。

## 8. 复测 v16 §8 的三个 SKIPPED 项

1. **C-1 的 callgrind 数字（756.7 → 728.5 指令/pair）无法复现，因此未获独立确认。**
   同配方、同机器、同编译器（g++ 15.2.0）下，**改前的基线源码**量到
   **769.53 指令/pair**（差分：两个运行长度，callgrind 确定性计数），
   与记录的 756.7 相差 +1.7%。本轮落地版 **778.54 指令/pair**，
   即相对基线 **+9.01（+1.17%）**——这是 A 的显式链接证明在**短链**上的代价
   （与 §1A 的"K=1 时耗时相同"一致）。
   ⇒ 结论：**基线值本身对不上**，所以 v16 §5 的 −3.7% 不应继续被引用；
   本轮的增量是受控测量（同机、同配方、同编译器，只有 core 不同）。
2. **两个 IDF 示例工程构建：已完成**（v16 记为未验证）。
   `examples/sensor_pipeline_esp32` 与 `examples/esp32_demo` 在 IDF v6.0.2 下
   `idf.py build` **均成功**（rc=0，bin 分别 0x2d5f0 / 0x2c400 字节，分区余量 82%/83%）。
3. **设备端重烧与抓取：未完成**（原因见 §7——验收固件链接失败）。
   ⇒ 本轮的**设备侧时间证据仍然来自仓库外的独立夹具**（同一颗 S3、同一 PM_DEBUG=0
   配置），而不是验收固件。**这一点不得含糊。**

## 9. 未做 / 待办

- **S3 验收固件的 DRAM 预算**（§7）——需要设计决定。
- **`validate()` 百分位的重取**：v14 的 512 次整理窗口 p50/p99 是在**改前**构建上取的，
  本轮之后应当重取（同一负载、同一固件路径）。
- **覆盖率未逐行归属**（§5）。
- **经典 ESP32 未接**：本机只看到 `/dev/ttyACM0`（S3），经典 ESP32 的 `sdkconfig` 停在
  `CONFIG_IDF_TARGET="esp32"`；切目标必须 `rm -f sdkconfig && idf.py set-target <t>`
  （IDF 不读 `sdkconfig.defaults.<target>`，且 defaults 列表里靠后的文件改不动
  `CONFIG_IDF_TARGET`）。**这一条已写进 v17，因为本轮真的踩了**（烧录报
  `This chip is ESP32-S3, not ESP32`）。
- `bins_find` 的 bin 内 best-fit **已在时间与空间两轴上实测更差**，`PM_SL_COUNT` 调大
  在**时间与空间两轴**上也都没有收益——两条都不要再猜（`bench/RESULTS.md` §9）。
- `get_stats()` 走遍所有空闲链**是契约的一部分**：只走最高非空 bin 的版本
  被两条具名用例（`tests/suite.cpp:3622`/`:3872`）挡下，**不要再试**。
