可以。核心架构已经完整，剩下的是实现参数，例如指针位宽、最大池数量、最大对象数量和具体整理算法。这些不会再改变总体设计。

# PondMerge v1 架构说明

## 1. 产品定位

PondMerge v1 是面向无 MMU MCU 的用户态托管内存系统。

它通过：

- 物理内存分区；
- 固定池化管理；
- 可搬迁对象；
- C++ 逻辑指针；
- 开发者显式触发整理；
- RAII 借用计数；

解决长时间运行中的内存碎片问题。

它不承诺普通裸指针可以自动跟随搬迁，也不在后台线程或中断中自动整理。

## 2. 三个内存区域

| 区域 | 管理者 | 规则 |
|---|---|---|
| Chaos Zone | 硬件、外设、驱动 | PondMerge 永远不触碰 |
| Free Zone | 开发者 | PondMerge 不管理、不整理 |
| Auto Zone | PondMerge | 只管理明确分配到这里的对象 |

v1 暂不使用 MPU 等硬件保护，因此三区主要是内存布局和软件契约。野指针仍可能跨区写坏数据。

Auto Zone 在启动时确定总大小，后续只能重新分配内部空间，不能凭空增加 RAM。

## 3. Pool 模型

Auto Zone 被划分为多个逻辑池，例如：

- 音频池；
- 视频池；
- 网络池；
- 临时池；
- 通用池。

每个池包含：

- `pool_id`
- 当前物理范围
- 对象描述符表
- 空闲空间信息
- 已用字节数
- `borrow_count`
- 结构版本号
- 当前状态

普通运行期间池的物理位置保持稳定。池合并和拆分属于显式迁移操作，完成后对象可能换池。

池状态包括：

```text
RUNNING
PAUSED
COMPACTING
MERGING
SPLITTING
```

## 4. 对象模型

每次分配都会创建一个稳定的对象编号：

```text
object_id
current_pool
physical_address
size
alignment
flags
generation
```

对象描述符位于固定元数据区域，不参与搬迁。

对象真正移动时，只更新描述符中的物理地址和版本号。对象编号保持不变。

因此，池 ID 表示“对象现在在哪个池”，而不是对象永久身份。

## 5. 自定义指针

PondMerge 的自定义指针不是普通物理地址，而是逻辑引用：

```text
object_id + object_offset + cached_address + cached_generation
```

`pm_ptr<T>` 可以长期保存。

使用时：

1. 检查缓存版本是否仍然有效；
2. 如果版本没变，直接使用缓存地址；
3. 如果对象被整理过，重新查描述符；
4. 更新缓存地址；
5. 返回当前物理地址。

这就是惰性更新。

C++ 中可以通过 `operator->` 提供接近普通指针的写法：

```cpp
pm_ptr<Packet> packet = pm_alloc<Packet>(pool);

packet->data[index] = value;
```

但它本质上仍是逻辑指针，不是普通 `Packet*`。

## 6. 池内和跨池引用

默认接口提供池内引用：

```cpp
pm_local_ptr<T>
```

需要跨池时，显式使用：

```cpp
pm_ptr<T>
pm_cross_ref<T>(...)
```

两者底层使用同一套对象描述符和惰性更新机制。

跨池引用可以正常处理：

- 目标池整理；
- 目标对象搬迁；
- 池合并；
- 池拆分。

目标对象释放后，引用失效。Debug 模式报告错误，Release 模式返回空指针或错误码。

## 7. 临时原生指针

高频代码可以临时获得普通 C++ 指针：

```cpp
{
    auto access = packet.borrow();

    access->data[index] = value;
}
```

`borrow()` 返回 RAII 对象：

- 创建时 `borrow_count + 1`
- 离开作用域时 `borrow_count - 1`
- 不允许忘记释放
- 建议设计为只能移动、不能复制

借用期间取得的普通指针有效，但对应池不能整理。

## 8. 整理规则

整理由开发者显式调用：

```cpp
pm_compact(pool);
```

整理流程：

1. 池进入 `PAUSED`；
2. 禁止新的 `borrow()`；
3. 检查 `borrow_count`；
4. 如果计数不为 0，立即返回 `BUSY`；
5. 移动可搬迁对象；
6. 更新对象描述符；
7. 更新对象版本号；
8. 池版本号增加；
9. 池恢复 `RUNNING`。

整理不会无限等待正在使用的指针。

整理期间必须保证：

- 没有线程使用该池的普通指针；
- 没有 ISR 保存该池的普通指针；
- 没有 DMA 正在访问该池；
- 没有外设正在使用该池缓冲区。

跨池访问如果目标池正在暂停，应返回 `BUSY` 或等待由调用方决定。

## 9. 池合并

池合并用于某个池空间不足、另一个池存在大量空闲空间的情况。

流程：

1. 暂停相关池；
2. 确认没有借用中的普通指针；
3. 选择目标池；
4. 迁移对象；
5. 保留原有 `object_id`；
6. 更新对象所属池和地址；
7. 释放旧池；
8. 恢复运行。

由于引用保存的是对象编号，已有的池内或跨池逻辑引用无需全部修改。

## 10. 池拆分

池拆分用于大池长期空闲、需要把空间重新分配给其他用途的情况。

流程：

1. 暂停源池；
2. 确认没有活跃借用；
3. 从预留 Auto Zone 中创建新池；
4. 选择需要迁移的对象；
5. 保留对象编号；
6. 更新对象所属池；
7. 完成新旧池的空间调整。

如果没有足够的预留空间，或者固定对象阻止拆分，操作返回失败。

## 11. 绝对不能直接搬迁的数据

以下数据必须放入 Chaos Zone，或者在 Auto Zone 中标记为 `pinned`：

- DMA 正在使用的缓冲区；
- 外设、显示、音频控制器正在使用的缓冲区；
- ISR 或其他线程仍持有普通物理指针的数据；
- 已把地址交给外部库、驱动但无法追踪生命周期的数据；
- 要求固定物理地址的数据；
- 含有未经处理的绝对内存指针的数据；
- 正在进行无锁并发访问的数据。

`pinned` 对象不会移动，但可能留下碎片。

v1 不自动分析对象内部的裸指针。对象内部引用必须使用：

- `pm_ptr`；
- 相对偏移；
- 或者由开发者提供明确的重定位处理。

## 12. 错误结果

所有管理操作都应返回明确结果：

```text
OK
BUSY
NO_SPACE
INVALID_POOL
INVALID_REFERENCE
PINNED_BLOCK
NOT_RELOCATABLE
ALREADY_PAUSED
```

不能整理时，PondMerge 必须失败返回，不能强行移动数据。

## 13. Debug 和 Release

Debug 模式建议开启：

- 对象边界检查；
- generation 检查；
- 释放后引用检查；
- 池归属检查；
- 跨池访问检查；
- `borrow_count` 状态检查；
- 内存填充和保护标记。

Release 模式可关闭部分边界检查，但不能破坏对象描述符和引用更新机制。

## 14. v1 明确不做的事情

- 不支持普通 `T*` 自动跟随搬迁；
- 不在后台自动整理；
- 不在中断中执行整理；
- 不自动修复对象内部的裸指针；
- 不凭空扩大 Auto Zone 总容量；
- 不提供硬件级三区越界保护；
- 不保证整理操作本身是硬实时的。

## 15. v1 最终承诺

PondMerge v1 可以提供：

> 在开发者暂停相关池、确认没有活跃物理指针和外设访问的前提下，对可搬迁对象执行显式整理、池合并和池拆分；长期保存的 C++ 自定义指针会在下次使用时惰性更新，而高频代码可以通过 RAII 借用获得普通原生指针。

这套定义下，架构已经闭合，后续主要进入接口、内存布局和实现参数设计阶段。
