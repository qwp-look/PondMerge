# PondMerge v1 第十八轮：夹具几何参数化（HANDOVER v20）

> 起因：v18 用"zone 入 PSRAM"绕开了验收夹具的 256 KiB 静态 zone，代价是夹具
> 不再代表内部 SRAM 内存等级，且经典 ESP32 从此编不进套件。本轮实现审计建议的
> A 路线：**夹具几何参数化**——段数量保持 64（被测试断言钉死），段尺寸变成
> 编译期旋钮 `PM_TEST_SEG_BYTES`，设备构建用 **1 KiB**（zone 64 KiB，纯 DRAM），
> host 默认 4 KiB（历史几何）。套件在两种几何下分别全绿。
>
> 基线：`1f3431a`。本轮提交：参数化 + 设备构建改造 + 双几何验证一笔，
> 文档一笔。

## 4. 参数化方法（给未来轮次的操作说明）

红驱动：改 `PM_TEST_SEG_BYTES` 跑套件 → 每个失败 CHECK 暴露一处几何耦合 →
把字面量改写成 `SEG` 的表达式（保持场景**意图**：跨边界、精确填充、洞 ≥ 阈值
等约束用 SEG 表达）→ 双几何分别全绿。经验：

- 块可以跨段，分配字节大小不约束几何；受约束的是**池窗口的段算术**与**精确
  填充/耗尽类断言**。
- 块尺寸按 8 对齐（`PM_ALIGNMENT`）：耗尽类测试的探测尺寸必须对齐后仍满足
  "N 个放下、N+1 个放不下"（R10 的 `(4*SEG/15) & ~7` 技巧）。
- 与阈值耦合的建议场景（fragment_min_bytes=512、100‰）：洞的相对比例必须
  保持（R31 用 `SEG/2` 的洞 = 125‰）。
- R35 的 `estimated_moved_bytes` 会计口径（Σ 移动块 + 一个头）在两种几何下
  实测一致，公式 `4×SEG − 3×(OP2+8)` 已入注释。
